# 发现：Qwen 图里没有「秩≥2 常量作逐元素第二操作数」——该怀疑方向被排除

记录时间：2026-10-13 21:3x
记录人：Lead
状态：**已实测确认**

## 背景

codex 会话的探针把逐元素算子按第二操作数的形态分了类，我据此重新读它
`build_models.py` 的**构造代码**（这一步很关键，只看结果标签会读错），得到规则：

**第二操作数是常量 initializer 时：**

| 形状 | 秩 | 结果 |
|---|---|---|
| `()` 标量 | 0 | ✅ 兼容（`c05_div_scalar`、`c06_mul_scalar`） |
| `(8,)` 向量 | 1 | ✅ 兼容（`c01_mul_vec`、`c02_add_vec`） |
| `(4,1)` 行 | 2 | ❌ 不兼容（`c03_div_row`、`c07_mul_row`） |
| `(4,8)` 满 | 2 | ❌ 不兼容（`c04_mul_full`、`c08_add_full`、`c09_div_full`） |

**第二操作数是运行时张量时：**

| 形状组合 | 结果 |
|---|---|
| `(4,8)` × `(4,8)` | ✅ 兼容，**且数值对账通过**（`d30_mul` oracle_pass=True err=0.0） |
| `(4,8)` × `(4,1)` | ✅ 兼容，**且数值对账通过**（`d32_div` err=0.0059） |

→ 规则是「**秩≥2 的常量**作逐元素第二操作数」，**不是**「同形逐元素算子不支持」。
证据是 `d30_mul` / `d32_div` 的 `compatibility=[0,0]` + `oracle_pass=True`。

## 对 Qwen 的检验（本次工作）

对 `qwen/s8-fixed-build/qwen_s8_fixed.onnx`（固定 batch=1/seq=8，3028 节点，
shape inference 成功，解析出 3124 个张量形状）逐个分类：

```
Add: runtime tensor   241
Mul: runtime tensor   292
Div: runtime tensor    49
合计 582 个逐元素算子，全部是运行时×运行时

预测会失败的情形（秩≥2 常量）：NONE
```

**结论：该规则完全解释不了 Qwen 的 `compatibility=1`。**
Qwen 的逐元素算子**全部落在设备已实测兼容的类别里**。
**这个怀疑方向被排除**，Qwen 不兼容另有原因。

## 剩下的怀疑（按优先级）

1. **规模**：3028 节点 / 980 MB / 290 initializers —— 但没有证据表明存在硬上限
2. **特定算子或组合**：`ConstantOfShape`、`Expand`、`Where`、`Gather`、`ReduceMean`、
   `Transpose`/`Reshape` 的某种组合模式
3. **`logits` 输出 151936 维**（fp16，约 2.4 MB）
4. **整体图结构**：LLM 的 prefill 形态（单次喂入整段序列 + causal mask）本身
5. **LLM 图不被支持**：CANN LM Engine 官方硬件门槛是 Kirin X90，
   而本机 `canIUse(AI.CANN.LLMEngine)=false` —— 这是一条**独立的强假设**
