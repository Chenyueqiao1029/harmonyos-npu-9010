## 一、核心结论：9020 和 9010 完全不是一个处境

### 决定性发现 1：`KirinX90` 就是 `Kirin9020`

**华为官方《基本架构》页原文**：

> 「**Kirin9020/KirinX90系列处理器**：耦合架构 —— 耦合架构是指 Cube 计算单元和 Vector 计算单元同核部署」

**佐证**：官方仓库 `cann-recipes-harmony-infer` 里
`ops/ascendc/src/gather_dequant_int8_custom/CMakePresets.json` L30 用的就是 `"kirin9020"`。

→ **工具链里的 `KirinX90` / `kirinx90` = 麒麟 9020 = Mate 70 系列。**

### 决定性发现 2：9020 与 Ascend 910B/910C 是「同代」架构

**华为官方《昇腾和麒麟同代AI处理器的映射关系》表 1**：

| 昇腾（Ascend） | 麒麟（Kirin） |
| --- | --- |
| Ascend910B、Ascend910C | **KirinX90、Kirin9030** |

**Ascend 910B/910C 是华为的数据中心 AI 训练/推理芯片。**

### 决定性发现 3：NPU 架构版本

**华为官方《概述》表 1 —— 处理器型号和 NPU_ARCH 的对应关系**：

| 处理器型号 | NPU_ARCH |
| --- | --- |
| Ascend910B / Ascend910C | 2201 |
| **KirinX90（=麒麟 9020）** | **3003** |
| Kirin9030 | 3113 |

### 测试 D（如果时间够）：走 CANN Kit 自定义算子

**这条路 9010 走不通，9020 官方支持。**

**官方给的两步改造**（`算子编译迁移指导`）：
```cpp
// ① 算子原型定义里注册目标平台
namespace ops {
class AddCustom : public OpDef {
public:
    AddCustom(const char* name) : OpDef(name) {
        this->AICore().AddConfig("ascend910b");
        this->AICore().AddConfig("kirinx90");   // ← 加这一行
    }
};
OP_ADD(AddCustom);
}
```
```json
// ② CMakePresets.json 的 ASCEND_COMPUTE_UNIT 改成 kirinx90
```

**官方 AscendC 支持的能力差异（编算子时必须知道）**：
```
· 不支持 GM 操作使能 L2 Cache           → 只影响性能
· 不支持原子操作                        → 需 DataCopy 搬回 GM
· 不支持 bfloat16_t；Cube 计算不支持 float → 换 half 并做数据转换
· 不支持 AI Core 核间同步（单核耦合架构）  → 别硬编码核数
· 不支持通信特性 / 训练特性
· 耦合架构（Cube+Vector 同核）
  → 不能用 ASCENDC_IS_AIV / ASCENDC_IS_AIC 区分编程
· 硬件规格必须从 Platform 取，禁止硬编码
```

## 五、风险与反面可能（必须写出来）

1. **`KirinX90` 是否严格等于 Mate 70 Pro 用的那颗 9020？**
   文档说「Kirin9020/KirinX90系列」，用的是"系列"二字 —— 可能同一系列下有差异。
   **明天用 `canIUse` 与实测数据来判定，不要拿文档当结论。**

2. **平台插件只影响自定义算子（AscendC 写的），可能与我们那批标准 ONNX 算子的
   compatibility 判定无关。**（我 10-13 就列过这条反面可能）
   → 所以**测试 A（HiAI Foundation 通路）优先级高于测试 D（CANN 自定义算子）**。

3. **设备侧 compatibility 判定用的是设备自己的算子表**，装插件不一定能改。
   → 只能靠实测。**不许把"官方文档说支持"当成"我们已经跑通"。**

4. **Mate 70 Pro 的 HiAI 版本号可能与 9010 不同**（我们是 106.636.120.010），
   版本差异可能导致行为不同。**先记下它的 `canIUse` 与 HiAI 版本再下判断。**

## 六、一句话总结

**麒麟 9020（KirinX90）在官方工具链里是有完整平台支持的，且与 Ascend 910B/910C 同代；
麒麟 9010 什么平台支持都没有 —— 这解释了我们在 9010 上的一切失败，也让明天值得认真试。**

**但"文档说支持"不等于"我们的模型能跑"，明天必须用 compatibility / Build / RunSync 三个判据实测，
拿到与 9010 可对照的数字，才算结论。**
