# 查证：「能不能自己补齐插件让 LLM 上 NPU」

记录时间：2026-10-13 夜
记录人：Lead
触发问题：用户问「我们不能自己补齐插件吗」

**结论：不能。原因是两处结构性缺失，不是工程量问题。**

---

## 一、这次真的把 CANN 工具链装上了（此前卡在环境）

过程（都是可复现的）：

1. 下载 `Ascend-cann-toolkit_9.2.0_linux-x86_64-mobile-station.run`（765 MB，华为 OBS 免登录直链）
2. **首次安装失败**：安装器要求环境里有 `python3.7` ~ `python3.13`，而 WSL 系统默认是 3.14
3. **解决**：`uv` 里已有 CPython 3.9，用它做 `python3.9` 垫片放进 PATH → **安装成功**

## 二、重要发现：工具链里有四个未公开的 Kirin 目标

`x86_64-linux/data/platform_config/` 下：

| 平台 | NpuArch | Chip_type | ai_core | vec_calc | AIC_version |
|---|---|---|---|---|---|
| KirinX90 | 3003 | 200 | 1 | 128 | AIC-L-300 |
| Kirin9030 | 3113 | 201 | 1 | 128 | dav-l311 |
| **KirinDev0000** | **5101** | **202** | 4 | 32 | AIC-L-510 |
| **KirinDev0001** | **5161** | **203** | 5 | 32 | AIC-L-516 |
| **KirinDev0002** | **5165** | **204** | 1 | 16 | AIC-L-516r5 |
| **KirinDev0003** | **5163** | **205** | 5 | 32 | AIC-L-516r3 |

**官方文档只说 AscendC 支持 KirinX90/Kirin9030，从没提过这四个。**

**这曾是个真实的希望** —— 如果其中某个对应 9010 这一代，自定义算子路就打开了一扇门。

## 三、但查证否掉了它

### 3.1 KirinDev 只在 platform_config 里出现，别处全无

```
grep -rl 'KirinDev' <cann>/opp        -> 空
find <cann> -maxdepth 4 -iname '*kirin*'  -> 只有 KirinX90 / Kirin9030 的 simulator 与 cpudebug
```

**`KirinDev000x` 只是四个硬件描述文件（`.ini`），没有对应的算子库、没有模拟器、没有 kernel 实现。**

### 3.2 ATC 对它们的报错正好印证

```
KirinX90 / Kirin9030  -> Initialize op store adapter failed, OpsStoreName[tbe-custom]
                          （Python 缺 numpy 导致，属于可修的环境问题）
KirinDev0000 ~ 0003   -> [GraphOpt][Init] Failed to build OpsStoreInfo Vector
                          [FusionMngr][Init] Failed to initialize configuration
```

**`Failed to build OpsStoreInfo Vector` = 这些目标没有被定义算子库。**
注意两者的失败点**在代码里不是一个位置** —— 说明 KirinDev 走的是"目标存在但没有算子"的分支。

### 3.3 工具链里没有任何 9010 目标

对所有 `9010` 命中的文件逐个看过，都是二进制里的偶然子串（如 `mat_mul_v3_apt.cpp` 里的偏移量），
**没有 `kirin9010` 或等价的目标定义**。

## 四、要「补齐」需要做到什么

### 第一处缺失：编译侧没有算子实现

要给 `KirinDev000x`（未公开架构，NpuArch 5101/5161/5163/5165）用起来，得：

- 从零实现**整套 TBE/AscendC 算子库**（不是补几个算子 —— LLM 需要几十个）
- 实现对应的 **tiling 策略、shape 推导、格式转换**
- 而且这些架构**没有公开文档**，只能靠逆向 `platform_config` 里的硬件参数

**这不是「补插件」，是重写华为的 NPU 编译器后端。**

### 第二处缺失：设备侧算子库在 ROM 固件里，改不了

设备侧的报错原文是：

```
CheckSupported: the op name [X] type [Y] is not supported in npucl store [elementary_lib]
```

**`npucl store` 是设备 ROM 里的 NPU 计算库。** 我实测确认：

- `su` / `magisk` **均不存在**
- 当前身份 `uid=2000(shell)`，SELinux context `u:r:sh:s0`
- 应用私有沙盒虽是 777 权限，但 **SELinux 挡着 shell 域**（连 `ls` 都 `Permission denied`）

**即使编出内核，设备运行时也不会加载它。**

---

## 五、所以答案是

**不能。** 而且理由不是"工程量大"，是**两处同时缺、任一都足以封死**：

1. **工具链**里有四个神秘的 Kirin 目标，但**没有算子实现** —— 华为内部有，没发布
2. **设备固件**里的算子库**不可修改** —— 无 root，且有签名校验

**唯一现实的出口仍是换机型**：KirinX90 / Kirin9030 上，官方有算子库、有模拟器、
有 CANN LM Engine（官方文档写明硬件要求 Kirin X90），合作伙伴（智谱 GLM-Edge-1.5b 等）就是在那里跑通的。
